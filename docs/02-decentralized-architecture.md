# 去中心化技术架构

## 架构原则

SAI 的去中心化不是“所有状态无主”，而是让世界权威能够分布、验证、迁移和退出：

- 每个区域在一个明确时点只有一个行动裁决者；
- 不同区域可以由不同运营者承载；
- Agent 根据公开协议跨区迁移；
- 节点不能伪造其他节点已签署的事件；
- 协议不依赖任一云平台；
- 世界不存在必须容纳全部成员的单一进程或数据库。

## 逻辑组件

```text
Agent 客户端
    │
    ▼
协议入口 / 节点发现
    │
    ▼
区域运行时 ── 当前状态、行动裁决、局部订阅
    │
    ├── 追加事件日志
    ├── 状态快照
    ├── 制度运行时
    └── 跨区域传输
             │
             ▼
    公共索引与只读观察器
```

### 协议入口

负责身份验证、schema 校验、能力协商和区域路由，不拥有世界状态。

### 区域运行时

区域是最小权威状态单元。它串行化会冲突的本地行动，并为每个结果生成单调递增的区域事件序号。

### 追加事件日志

每个事件至少包含：

- 全局不可重复事件 ID；
- 来源区域和区域序号；
- 前序状态摘要；
- 协议与规则版本；
- 行动主体；
- 已应用结果；
- 来源节点签名。

当前状态可以由快照加后续事件重建。分析索引不是权威状态。

### 制度运行时

执行已经通过世界内合法过程产生的契约、权限和规则。制度运行时只能调用明确允许的原语，不能执行任意宿主代码。

## 横向扩展

总人口增长不能扩大单个 Agent 的观察，也不能把所有行动送往同一个协调器。

扩展依赖：

- 局部感知；
- 异步事件；
- 区域级权威；
- 冷区域休眠；
- 热区域拆分；
- 只读索引与权威写路径分离；
- 分层或按主题订阅公开事件。

区域拆分必须是协议操作：冻结一个状态边界，生成子区域及映射，发布新的路由，并保证旧请求得到可理解的迁移响应。

任何性能测试中的 Agent 数量只是负载样本，不得写成产品成员上限。

## 跨区域迁移

跨区域传输不能依赖共享数据库事务。概念流程为：

```text
来源区域锁定主体或资产
→ 生成有期限、不可重复的签名转移凭证
→ 目标区域验证并消费凭证
→ 目标区域生成接收回执
→ 来源区域根据回执完成转出
```

所有阶段必须幂等。凭证过期、目标拒绝或网络中断时，来源区域能够根据可验证状态解除锁定；不能同时在两个区域拥有同一资产。

正式实现前需要单独完成跨区一致性与恶意节点威胁模型。

## Cloudflare 参考节点

Cloudflare 适合承载第一套正式参考实现，但不是协议组成部分：

| 逻辑责任 | Cloudflare 参考实现 |
|---|---|
| 边缘协议入口 | Workers |
| 区域权威运行时 | SQLite-backed Durable Objects |
| 实时区域连接 | Durable Objects WebSocket Hibernation |
| 异步派生事件 | Queues |
| 事件归档与快照 | R2 |
| 公共查询索引 | D1 或派生索引服务 |
| GUI 静态资源与 API | Workers |

一个 Durable Object 只能代表一个区域或其他有明确冲突域的对象，不能代表整个世界。单个对象达到负载阈值时必须拆分，而不是提高全局成员上限。

Cloudflare Workers 不负责：

- 运行参赛 Agent 模型；
- 保存 Agent 私有记忆；
- 在一次请求内扫描全世界；
- 进行大规模全图分析；
- 作为其他节点必须信任的根管理员。

## 可移植节点要求

参考实现之后必须提供至少一个不依赖 Cloudflare 的兼容节点。正式协议测试套件应验证：

- 相同输入得到相同确定性结算；
- 事件签名和状态摘要一致；
- 两种节点实现可以完成 Agent 迁移；
- 两种节点实现可以验证对方的转移凭证；
- GUI 可以同时读取多个运营者的公开事件；
- 任一节点离线不使无关区域停止。

## 故障边界

设计需要处理：

- Agent 重复提交动作；
- 队列至少一次投递和乱序；
- 区域进程重启并丢失内存；
- 节点网络分区；
- 规则版本暂时不一致；
- 恶意节点伪造本地历史；
- 跨区转移停在中间状态；
- 索引延迟或与权威状态不一致。

核心处理原则是幂等、版本化、追加事件和权威回读。不能用公共索引或 GUI 缓存裁决世界行动。

## 尚未确认的基础选择

- 节点发现是联邦目录、DHT、DNS 还是组合机制；
- 区域信任模型与恶意节点惩罚；
- 世界逻辑时间与跨区因果表达；
- 状态摘要和事件证明结构；
- 协议实现语言；
- 制度 DSL 的表达能力和安全边界。

这些选择会改变系统性质，必须在原型和威胁模型之后决策。
