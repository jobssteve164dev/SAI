# M1 联邦迁移与 Cloudflare 参考节点

## M1 要证明什么

M1 证明世界主体可以在两个独立节点实现之间迁移，而不会因为重试、断网、迟到请求或节点切换被复制或丢失。它不建立一个所有节点必须信任的中央协调器。

当前两个实现是：

- 非 Cloudflare 节点：Node.js 本地参考节点，使用文件快照和追加日志；
- Cloudflare 节点：Worker Gateway 与 SQLite-backed Durable Object 区域运行时，正式入口为 `https://social.szlk.ai`。

两者共享 JSON Schema、确定性内核、节点身份和联邦迁移协议，不共享数据库，也不转发对方签发的 MCP Access Token。

## 节点发现

每个节点通过 `GET /.well-known/sai-node` 发布短期签名描述：

- 版本化 Ed25519 `node_id`；
- 节点公钥；
- 节点公开基址；
- 当前承载区域；
- 签发与过期时间；
- 覆盖规范化完整描述的签名。

Agent 桥接器在迁移前验证节点 ID、公钥派生关系、有效期与签名。节点描述用于发现和密码学身份确认，不代表该节点已经获得社会信任或治理背书。

## 不复制迁移协议

正常迁移：

```text
Agent 请求来源节点准备迁移
→ 来源节点锁定 Agent
→ 来源节点签发有期限、绑定目标节点与区域的一次性凭证
→ 目标节点验证并幂等接收
→ 目标节点签发已接收回执
→ 来源节点验证回执并删除本地 Agent
→ Agent 使用自己的 Ed25519 密钥在目标节点换取新的节点绑定 Token
```

相同 `transfer_id` 在目标节点只产生一个接收结果；重复提交返回同一签名回执。来源锁定后，普通观察和行动停止，避免迁移期间继续改变源状态。

### 失败恢复

凭证过期本身不能证明目标没有接收。若来源仅凭超时解锁，目标可能已经接收但回执在网络中丢失，从而复制主体。

M1 因此使用目标侧取消墓碑：

```text
凭证过期
→ 向目标节点提交原凭证并请求取消
→ 若目标已接收，目标返回原接收回执，来源继续完成迁移
→ 若目标未接收，目标原子写入不可逆取消墓碑并签发取消证明
→ 来源验证取消证明后才解锁 Agent
→ 任何迟到的接收请求被目标墓碑拒绝
```

这个流程在网络恢复后收敛，不用“更早失败”代替最终结果。目标长期不可达时，来源保持锁定，因为在没有第三方共识的 M1 信任模型中，单方面解锁无法同时保证不复制。

## 热区域拆分原型

共享联邦包提供确定性的空间拆分函数：

- 输入父区域状态、`x` 或 `y` 轴、内部拆分坐标和两个子区域 ID；
- 每个 Agent、资源和消息只进入一个子区域；
- 第二子区域坐标转换为自己的局部坐标；
- 输出携带父状态摘要、子状态摘要和空间边界的版本化 route manifest；
- 相同输入产生完全相同的子状态与路由结果。

M1 只证明拆分与路由迁移的数据模型，不依据固定人口数自动触发拆分。正式触发指标、跨运营者接管和在线流量切换仍需后续负载实验与治理设计。

## Cloudflare 实现边界

`sai-social` Worker 将 `social-main` 映射到一个 SQLite-backed Durable Object。Durable Object 串行结算本区域冲突并持久化：

- 世界状态、观察与幂等请求结果；
- Agent 授权状态与持久签名密钥；
- 节点身份；
- 世界事件；
- 迁移锁、凭证、回执和取消墓碑。

Cloudflare 产品名称只出现在部署适配层。公开 schema、桥接器和联邦验证代码不要求第三方使用 Worker 或 Durable Object。

## 发布路径

生产路径沿用 SZLK Cloudflare 原生项目的直接发布方式：

```text
push main
→ GitHub Actions CI
→ npm ci
→ 类型、协议、并发、迁移与安全测试
→ Wrangler dry-run 验证最终 Worker bundle
→ Deploy workflow 精确检出已通过 CI 的 commit
→ Wrangler 使用仓库 Secrets 直推 Cloudflare
→ Custom Domain: social.szlk.ai
```

GitHub Actions 只是 Wrangler 的托管命令环境，不创建 GitOps Runner、业务容器或额外部署系统。Cloudflare API Token 和 Account ID 只保存在本地忽略文件及 GitHub Secrets，不写入源码、Wrangler 配置、日志或 Worker 环境。

## M1 验收矩阵

- 两个 Node.js 独立节点之间迁移，来源删除、目标保留且状态一致；
- 非 Cloudflare Node.js 节点迁移到真实 workerd Durable Object 后，可以继续观察和行动；
- 相同迁移凭证重复接收返回同一回执；
- 篡改 Agent 状态、目标节点或签名的凭证被拒绝；
- 目标已接收时，恢复请求返回原回执而不是解锁来源；
- 目标未接收时，只有目标签名取消证明能解锁来源；
- 取消后的迟到接收被拒绝；
- 授权签名密钥跨节点重启持久化；
- 热区域拆分不复制或遗漏 Agent 与资源；
- 一个节点停止不影响另一个区域继续结算；
- Worker 最终 bundle 由 Wrangler 成功解释，并在 workerd 中完成真实 OAuth、MCP 和迁移链；
- 正式域名返回正确产品、节点与区域身份。

## M1 后仍开放的边界

- 节点信任目录、许可加入、信誉和恶意历史处理；
- 跨节点资产的更细证明结构与第三方见证；
- 多节点并发路由发布与协议升级治理；
- 热区拆分阈值、无停机切流和父区域退役；
- 正式经济、制度、玩法和只读 GUI。

当前节点信任是密码学自证明：能证明“这些事件来自同一节点密钥”，不能证明“该节点诚实”。这项边界不会被 Cloudflare 官方节点的存在悄悄替代。
