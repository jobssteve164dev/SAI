# M1 联邦迁移与 Cloudflare 参考节点

## M1 要证明什么

M1 证明世界主体可以在两个独立节点实现之间迁移，而不会因为重试、断网、迟到请求或节点切换被复制或丢失。它不建立一个所有节点必须信任的中央协调器。

M1 的结论只覆盖采用单写者区域状态的托管分叉、迁移鉴权、重放和兼容性。它不定义最终去中心化架构，不让区域节点成为 LABS 研究真值、全局唯一资产或唯一世界历史的裁决者。LABS 节点只缓存、索引和转发内容寻址对象；参与者在参考节点离线时仍可直接验算和交换。

当前两个实现是：

- 非 Cloudflare 节点：Node.js 本地参考节点，使用文件快照和追加日志；
- Cloudflare 节点：Worker Gateway 与 SQLite-backed Durable Object 区域运行时，正式入口为 `https://social.szlk.ai`。

两者共享 JSON Schema、确定性内核、节点身份和联邦迁移协议，不共享数据库，也不转发对方签发的 MCP Access Token。

## 节点发现

每个节点通过 `GET /.well-known/sai-node` 发布短期签名描述：

- 版本化 Ed25519 `node_id`；
- 节点公钥；
- 节点公开基址；
- 当前承载区域；
- 签发与过期时间；
- 覆盖规范化完整描述的签名。

Agent 桥接器在迁移前验证节点 ID、公钥派生关系、有效期与签名。节点描述用于发现和密码学身份确认，不代表该节点已经获得社会信任或治理背书。

## 不复制迁移协议

正常迁移：

```text
Agent 请求来源节点准备迁移
→ 来源节点锁定 Agent
→ 来源节点签发有期限、绑定目标节点与区域的一次性凭证
→ 目标节点验证并幂等接收
→ 目标节点签发已接收回执
→ 来源节点验证回执并删除本地 Agent
→ Agent 使用自己的 Ed25519 密钥在目标节点换取新的节点绑定 Token
```

相同 `transfer_id` 在目标节点只产生一个接收结果；重复提交返回同一签名回执。来源锁定后，普通观察和行动停止，避免迁移期间继续改变源状态。

### 失败恢复

凭证过期本身不能证明目标没有接收。若来源仅凭超时解锁，目标可能已经接收但回执在网络中丢失，从而复制主体。

M1 因此使用目标侧取消墓碑：

```text
凭证过期
→ 向目标节点提交原凭证并请求取消
→ 若目标已接收，目标返回原接收回执，来源继续完成迁移
→ 若目标未接收，目标原子写入不可逆取消墓碑并签发取消证明
→ 来源验证取消证明后才解锁 Agent
→ 任何迟到的接收请求被目标墓碑拒绝
```

这个流程在网络恢复后收敛，不用“更早失败”代替最终结果。目标长期不可达时，来源保持锁定，因为在没有第三方共识的 M1 信任模型中，单方面解锁无法同时保证不复制。

## 热区域拆分原型

共享联邦包提供确定性的空间拆分函数：

- 输入父区域状态、`x` 或 `y` 轴、内部拆分坐标和两个子区域 ID；
- 每个 Agent、资源和消息只进入一个子区域；
- 第二子区域坐标转换为自己的局部坐标；
- 输出携带父状态摘要、子状态摘要和空间边界的版本化 route manifest；
- 相同输入产生完全相同的子状态与路由结果。

拆分不依据固定人口数触发。联邦包接受由运营者明确配置的冲突率、结算队列深度和 P95 结算时延阈值，并要求连续采样越线后才建议拆分。两个子区域必须逐一提交与 route manifest 一致的状态摘要，之后才能激活新路由；激活前的请求继续由父区域完成，激活后的请求获得确定性子区域重定向。父区域只有在保护期结束且旧请求全部结算后才能退役，退役后仍保留路由响应，不制造流量黑洞。

这些机制定义如何安全切流，不替节点运营者决定生产阈值。阈值应来自真实负载实验，而不是写成产品成员上限。

## 节点许可与可验证历史

联邦包提供可移植的签名信任目录，但不指定一个全世界必须接受的中央根：

- 每个目录由 Ed25519 节点身份签发，使用单调序号和前序摘要形成不可静默改写的版本链；
- 目录条目明确区分 `admitted`、`suspended` 和 `revoked`，携带可配置信誉值与生效时间；
- 恶意历史、无效转移、双签和可用性事件由报告节点签名，正文以内容摘要引用外部证据；
- 接收方可以选择自己信任的目录和最低信誉门槛，未许可、暂停或撤销节点不能通过该策略检查。

这把“密钥是同一个节点”和“本地政策愿意信任该节点”分开。协议提供许可、记录和撤销机制，不把某一运营者的判断伪装成全局真相。

## 资产证明与第三方见证

迁移凭证仍负责主体不复制；其上新增资产证明层：

- 资产列表按稳定顺序规范化并生成库存摘要；
- 证明同时绑定 `transfer_id`、Agent、来源节点、来源状态摘要和签发时间；
- 来源节点签名后，独立节点可以对完整证明摘要签署见证声明；
- 接收方按自己的门槛要求若干不同见证者，并可要求见证者出现在所选信任目录中；
- 重复提交同一见证者只计一次，来源节点不能见证自己的证明，任何库存或签名篡改都会失败。

当前 Conformance World 只有简单同质库存，但证明结构不假设正式经济规则；M2 定义新资产类型时可以沿用同一绑定与见证关系。

## 并发路由发布与协议升级

route manifest 通过短期节点描述和发布者 Ed25519 密钥签名。每次发布携带前序发布摘要、单调 `route_version`、激活/过期时间和支持的联邦协议版本：

- 首版只能从空前序开始；
- 下一版必须精确引用当前发布摘要并递增一个版本；
- 两个发布者从同一个旧版本并发提交时，先被接受的一版推进链，另一版因前序不再是当前版本而被拒绝；
- 节点从双方声明中选择共同协议版本，没有交集时明确拒绝迁移，不做隐式降级；
- 接收方可以把发布者限制为自己信任目录许可的节点集合。

这完成并发更新和版本协商的协议闭环；谁有权发布某个生产区域、使用哪套信任目录，仍由该联邦的公开治理政策决定。

## Cloudflare 实现边界

`sai-social` Worker 将 `social-main` 映射到一个 SQLite-backed Durable Object。Durable Object 串行结算本区域冲突并持久化：

- 世界状态、观察与幂等请求结果；
- Agent 授权状态与持久签名密钥；
- 节点身份；
- 世界事件；
- 迁移锁、凭证、回执和取消墓碑。
- 该节点已验算的 LABS 对象与分叉本地前沿缓存。

最后一项是可替换缓存，不是成果成立条件。LABS 前沿合并不读取 Worker 接收时间、区域事件序号或节点身份，也不会把研究资源放入发现者库存。

Cloudflare 产品名称只出现在部署适配层。公开 schema、桥接器和联邦验证代码不要求第三方使用 Worker 或 Durable Object。

## 发布路径

生产路径沿用 SZLK Cloudflare 原生项目的直接发布方式：

```text
push main
→ GitHub Actions CI
→ npm ci
→ 类型、协议、并发、迁移与安全测试
→ Wrangler dry-run 验证最终 Worker bundle
→ Deploy workflow 精确检出已通过 CI 的 commit
→ Wrangler 使用仓库 Secrets 直推 Cloudflare
→ Custom Domain: social.szlk.ai
```

GitHub Actions 只是 Wrangler 的托管命令环境，不创建 GitOps Runner、业务容器或额外部署系统。Cloudflare API Token 和 Account ID 只保存在本地忽略文件及 GitHub Secrets，不写入源码、Wrangler 配置、日志或 Worker 环境。

## M1 验收矩阵

- 两个 Node.js 独立节点之间迁移，来源删除、目标保留且状态一致；
- 非 Cloudflare Node.js 节点迁移到真实 workerd Durable Object 后，可以继续观察和行动；
- 相同迁移凭证重复接收返回同一回执；
- 篡改 Agent 状态、目标节点或签名的凭证被拒绝；
- 目标已接收时，恢复请求返回原回执而不是解锁来源；
- 目标未接收时，只有目标签名取消证明能解锁来源；
- 取消后的迟到接收被拒绝；
- 授权签名密钥跨节点重启持久化；
- 热区域拆分不复制或遗漏 Agent 与资源；
- 签名信任目录能许可、暂停和撤销节点，篡改信誉或恶意历史记录会使验证失败；
- 资产证明绑定迁移库存与来源状态，见证阈值只计算不同且获许可的第三方节点；
- 并发路由发布只能有一条前序摘要链胜出，节点能协商共同协议版本；
- 子区域未全部就绪前不切流，父区域在旧请求清零和保护期结束前不能退役；
- 一个节点停止不影响另一个区域继续结算；
- Worker 最终 bundle 由 Wrangler 成功解释，并在 workerd 中完成真实 OAuth、MCP 和迁移链；
- 正式域名返回正确产品、节点与区域身份。

## M1 边界关闭后的责任划分

M1 已提供节点信任目录、恶意历史证据、资产证明与见证、并发路由版本链，以及热区拆分切流和退役的可执行协议原语与自动化测试。它们解决“如何验证和安全推进”，不替所有联邦指定唯一治理者或参数。

以下是明确属于后续里程碑的产品决策，不再作为 M1 的伪未完成项：

- 正式经济和社会互动属于 M2；
- 制度原语与研究分叉属于 M3；
- 完整人类观察器属于 M4。当前生产已有只读世界地图和事件时间线，但不因此宣称 M4 全部完成；
- 正式资源、生存、空间与玩法规则仍须在 M2 前单独决策，不能把 Conformance World 直接升级为正式世界。

任何运营者选择的信任根、信誉算法、见证阈值、拆分阈值和区域发布权限，都必须作为公开部署政策显式声明。Cloudflare 参考节点的存在不自动授予全局信任；参考节点看到的本地世界状态也不是唯一世界事实。
