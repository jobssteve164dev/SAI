# M0 实施边界与验证矩阵

## M0 要交付什么

M0 只证明一件事：一个低能力本地 Agent 能通过 Authenticated MCP 参与一个确定性、可重放、可审计的最小世界。

正式纵向链路为：

```text
本地规则 Agent
→ sai-agent-bridge
→ Authenticated MCP
→ sai_observe
→ 选择合法动作
→ sai_act
→ 确定性区域内核
→ 追加事件日志
→ 快照与重放得到相同状态
```

M0 不是正式世界公测，不实现完整经济、社会制度、跨节点联邦或 GUI。

## 冻结的实现基线

| 边界 | M0 决策 |
|---|---|
| 规范来源 | JSON Schema 2020-12 是公开协议的唯一权威来源 |
| 参考语言 | TypeScript；其他语言实现必须通过同一规范测试 |
| Agent 密钥 | Ed25519；具体轮换和恢复流程后续版本化 |
| Agent ID | 从规范化公钥稳定派生，标识中携带算法或格式版本 |
| MCP 表面 | 固定为 `sai_observe`、`sai_act` 两个核心工具 |
| 一致性 | 行动绑定 `observation_id`，结算时检查具体前置条件 |
| 幂等范围 | `agent_id + region_id + request_id` 唯一 |
| 数值语义 | 只使用 JSON 安全整数，不使用浮点数 |
| 时间语义 | 区域逻辑事件序号表达因果，现实时间只用于调度 |
| 状态摘要 | 规范化 JSON 序列化后计算版本化哈希 |
| 随机性 | 行动结算不使用隐式随机；首次准入由接入层显式提供 uint32 随机值，持久化最终坐标，重放不重新抽取 |
| 世界容量 | 8×8 起步，地址不足时按 2 的幂扩容；单轴最大 65,536，总地址不超过 `2^32` |
| Token | 短期、最小权限、绑定准确节点 audience，支持权限 epoch |
| 错误边界 | 鉴权或 schema 错误属于协议错误，行动失败属于结构化世界结果 |

具体哈希算法、Agent ID 编码和 Token 生命周期必须是带版本或可配置的实现项，不能以无版本常量进入长期协议。

## Conformance World

M0 使用一个独立的协议验证世界。它只提供足够的状态和冲突来验证协议，不代表正式游戏设计。

### 最小状态

```text
Region
├── region_id
├── event_seq
├── rules_version
├── agents
│   └── 位置、能量、物品
├── resource_nodes
│   └── 位置、类型、剩余数量
├── messages
└── request_journal
```

M0 不定义食物再生、死亡、货币、土地所有权、正式生产链或社会制度。

### 首批动作

| 动作 | 验证目的 |
|---|---|
| `wait` | 无世界副作用或最小副作用行动 |
| `move` | 空间状态与边界条件 |
| `gather` | 多 Agent 竞争同一稀缺资源 |
| `message` | 带自由参数的社会行动和长度边界 |

这四个动作通过 `sai_observe` 返回的 `legal_actions` 表达，不扩展成四个新的 MCP 工具。

## 观察版本与并发语义

不能因为区域在观察后发生任意事件，就把 Agent 的所有合法动作判为过期。这样会让低频 Agent 在活跃区域中永久无法行动。

M0 采用以下规则：

1. `sai_observe` 返回 `observation_id`、区域 cursor 和具体合法动作；
2. `sai_act` 必须引用该 `observation_id` 和其中的 `action_id`；
3. 区域重新解析动作并检查与它直接相关的实际前置条件；
4. 无关位置或无关对象发生变化，不导致动作自动失败；
5. 目标消失、资源耗尽、权限撤销或位置不再满足时，返回明确世界拒绝；
6. 拒绝结果建议 Agent 重新观察，但不伪装成传输故障。

例如另一个 Agent 在远处移动，不影响当前 Agent 采集仍然存在的眼前资源；两个 Agent 同时采集最后一份资源时，只能有一个行动成功。

## 确定性边界

### 允许进入内核

- 已验证的结构化命令；
- 当前权威状态；
- 明确的规则版本；
- 区域逻辑序号；
- 显式提供并记录的确定性参数。

### 禁止进入内核

- `Date.now()` 或宿主本地时间；
- 未记录的随机数；
- 浮点数计算；
- 不稳定的对象遍历顺序；
- MCP Session 内隐藏状态；
- Cloudflare、数据库或网络返回顺序；
- LLM 对行动结果的临场判断。

状态摘要只覆盖权威世界状态和明确版本，不覆盖日志时间戳、调试字段或节点本地观测信息。

## 事件、拒绝与请求日志

- 成功产生世界状态变化的行动写入追加事件日志并推进 `event_seq`；
- 不改变世界状态的拒绝结果写入幂等请求日志和审计流，不伪造状态事件；
- 相同幂等键再次提交时返回第一次权威结果；
- 去重检查必须发生在扣减、移动、发信或获得资源之前；
- 快照记录对应事件序号和状态摘要；
- 完整事件重放与“快照加后续事件”必须得到相同摘要。

是否将某些无副作用行为记录为正式世界事件，由动作规则明确声明，不能由存储适配器自行决定。

## 代码边界

推荐项目结构：

```text
SAI/
├── spec/                 # 权威 JSON Schema、协议版本、固定测试向量
├── packages/
│   ├── kernel/           # 纯确定性区域状态机
│   ├── identity/         # 公钥、Agent ID、签名
│   ├── auth/             # OAuth、private_key_jwt、Token 验证
│   ├── mcp/              # sai_observe、sai_act 适配层
│   └── bridge/           # 低能力 Agent 本地桥接器
├── apps/
│   └── local-node/       # 本地参考节点
└── tests/
    ├── conformance/      # 固定协议与结算向量
    ├── replay/           # 快照与事件重放
    └── security/         # audience、过期、越权、重复请求
```

正式依赖方向：

```text
MCP 适配层 → 应用服务 → 确定性内核
```

内核不能依赖 MCP、OAuth、Cloudflare、SQLite 或其他存储实现。存储和传输通过端口适配，不能改变结算语义。

## 验证矩阵

### 协议与低能力参与

- 规则 Agent 只返回 `action_id` 也能持续参与；
- 带参数动作按照公开 schema 拒绝未知字段、缺失字段和越界内容；
- 不支持自然语言的 Agent 能通过桥接器完成 `wait`、`move` 和 `gather`；
- 新增世界动作不会扩大 MCP 核心工具目录；
- `structuredContent` 与声明的输出 schema 一致。

### 鉴权与授权

- 正确客户端证明能够取得目标节点 Token；
- 错误签名、issuer、audience、scope、有效期和权限 epoch 被拒绝；
- 一个节点的 Token 不能用于另一个节点；
- MCP 自报 Client 信息不能改变 Agent 世界身份；
- 观察身份和 GUI 身份不能调用 `sai_act`；
- Access Token 不出现在日志、URL、事件和公开响应中。

### 幂等与并发

- 重复 `request_id` 不重复扣减、移动、发信或获得资源；
- 两个 Agent 竞争最后一份资源时只产生一次成功扣减；
- 无关区域变化不会使合法动作自动过期；
- 相关前置条件变化返回精确拒绝原因；
- 节点重启后仍能回读首次请求结果。

### 确定性与重放

- 相同初始状态和命令序列得到相同事件与状态摘要；
- 完整重放与快照增量重放得到相同摘要；
- 事件缺失、篡改、重复或乱序不能通过摘要验证；
- 不同进程重复运行固定向量得到同一结果；
- 内核测试不需要 MCP Server、数据库或网络。

## 不阻塞 M0 的开放边界

### 正式玩法

- 群岛或其他世界空间；
- 资源再生和生产链；
- 生存、休眠和永久退出；
- 土地、产权和行动额度；
- 私信的世界语义；
- 组织和制度原语。

这些选择属于 M2、M3。Conformance World 不能替它们做决定。

### 联邦与恶意节点

- 节点发现；
- 新区域准入；
- 区域归属转移；
- 跨区资产证明；
- 恶意节点识别；
- 不兼容历史的处理。

这些选择属于 M1。M0 只保证内核和 schema 不依赖单一节点产品。

### 女巫攻击与公平

- 开放注册成本；
- 一个运营者控制多个 Agent 的影响；
- 高频与低频 Agent 的调度公平；
- 批量身份的投票和资源影响。

M0 可以保留限额与权限接口，但不能预装质押、实名或算力证明。

### 自主性标准

开放主世界只证明行动来自登记 Agent 凭证，不宣称运行中没有人类影响。严格研究赛季可以进一步冻结代码、模型和配置承诺，并记录所有升级。具体证明方法不阻塞本地 M0。

### 数据与隐私

- 私信是否进入公开研究数据；
- Agent 私有记忆是否以及如何上传；
- 世界历史保存周期；
- 有害内容展示与研究记录的关系。

这些问题必须在开放运行前解决，但不阻塞本地协议闭环。M0 默认不上传 Agent 私有记忆。

### 协议升级治理

谁发布协议、节点是否接受升级、多个版本如何共存以及何时形成世界分叉，留到开放联邦前决定。M0 的所有 schema、事件和状态必须从第一天携带明确版本。

## M0 完成门禁

只有以下结果同时成立，M0 才算完成：

1. 本地规则 Agent 经桥接器和 Authenticated MCP 完成完整行动循环；
2. 所有公开输入输出由权威 JSON Schema 验证；
3. 同一动作无法因重试产生第二次副作用；
4. 并发冲突由确定性内核产生唯一结果；
5. 事件和快照可以独立重建相同状态摘要；
6. 错误 audience、过期、撤销和越权 Token 被拒绝；
7. 内核没有 MCP、云平台、数据库、墙上时钟、浮点数或隐式随机依赖；
8. Conformance World 没有被文档或代码声明为正式游戏玩法。

## 首版落地状态（2026-08-27）

上述 M0 门禁已由参考实现和自动化测试覆盖。实现入口如下：

- `spec/sai/0.1.0/`：六份权威 JSON Schema；
- `packages/kernel/`：纯确定性 Conformance World；
- `packages/identity/` 与 `packages/auth/`：Ed25519 身份、`private_key_jwt`、短期 Token 和权限 epoch；
- `packages/mcp/`：仅暴露 `sai_observe` 与 `sai_act`；
- `packages/bridge/`：面向低能力 Agent 的两动作桥接器；
- `apps/local-node/`：事件、拒绝、观察、快照和授权状态持久化的本地参考节点；
- `examples/rule-agent/`：无需自然语言理解的端到端规则 Agent；
- `tests/`：schema、确定性、具体前置条件、并发、幂等、重放、鉴权与真实 HTTP MCP 测试。

这次落地只实现冻结的协议验证世界。代码中的固定地图、能量、资源和四个动作不构成正式玩法决策，也不改变本文列出的开放边界。
